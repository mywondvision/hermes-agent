## Исходное состояние (проверено)

- Первый пилот: Codex изменил два файла за 110 с под MXC; граница выдержала; 15 из 27 fixture-тестов падали из-за одной ошибки, которую Codex не мог увидеть без тестов.
- Тестовое окружение `D:\AI\envs\hermes-pm-ingress-test-20261106` ставит пакет в режиме editable: его finder указывает на модули основной рабочей копии, а база интерпретатора лежит внутри рабочей копии (`pyvenv.cfg`, `home`).
- В текущем профиле пилота у команд Codex нет чтения тестового окружения и интерпретатора.

## Предлагаемое решение (предложение исполнителя, INFERRED)

1. **Окружение тестов для попыток** вне рабочих копий: копия базового интерпретатора в
   `D:\SymphonyRuntime\test-python` и копия venv в `D:\SymphonyRuntime\test-env` с `pyvenv.cfg` на эту копию и **без**
   editable-установки (файлы `__editable__*` удаляются в копии), чтобы тесты импортировали код только из каталога
   попытки. Исходное окружение и рабочая копия не меняются.
2. **Профиль** `symphony-pilot` дополняется чтением этих двух каталогов. Остальное без изменений: запрет всего,
   кроме минимума, запись только в попытку, сеть команд выключена, MXC, чистое окружение клиента. В
   `shell_environment_policy.set` задаются `TEMP`/`TMP` внутри попытки и `PYTHONPATH` = каталог копии.
3. **Задача** (из открытых замечаний ревью среза attempt-workspace): разбор SDDL в
   `plugins/symphony_pm/transport/windows_read_boundary.py` (`_ACE`, `_split`) не понимает условные ACE со скобками
   внутри; исправить разбор и добавить fixture-тесты в `tests/plugins/test_symphony_pm_attempt_workspace.py`. Codex
   может сам запускать `python -m pytest` по этому файлу внутри песочницы.
4. **Цикл исправления.** После `codex exec` стенд снимает patch и проверяет его в отдельной копии
   (`git apply`, `ruff`, `scripts/run_tests.sh` по затронутым тестам). Если проверка не прошла — один второй
   `codex exec` с отчётом об ошибках в той же попытке, затем повторная проверка. Больше циклов нет.
5. **Остальное как в первом пилоте:** предпроверка без модели, зонд первой командой, Job с kill-on-close, лимит
   40 минут на запуск, сверка хоста, patch не применяется к рабочей копии без решения владельца.

## Acceptance

- A1. Предпроверка и зонд изнутри `exec` — только отказы вне попытки, окружение без секретов; чтение тестового
  окружения разрешено и не открывает `CODEX_HOME`.
- A2. Codex запускал тесты внутри песочницы (видно в журнале `--json`).
- A3. Итоговый patch проходит `git apply`, `ruff` и `scripts/run_tests.sh` в отдельной копии — с первого раза или
  после одного цикла исправления.
- A4. Хост до и после без изменений.

- ресурсы ниже порогов (RAM ≥ 1 ГБ, файл подкачки ≥ 3 ГБ, диск ≥ 5 ГБ).
