- Под MXC на этом ПК команды Codex получили отказ на чужую запись, чтение по пути и по идентификатору файла, жёсткую ссылку, ключ реестра, loopback и внешнюю сеть; закрытие Job остановило клиента и потомка.

- `codex sandbox` применяет `shell_environment_policy`: при `inherit = "core"` и `ignore_default_excludes = false` переменная-приманка с `TOKEN` в имени до команды не дошла.
- `codex exec` (CLI 0.167.0) поддерживает `--skip-git-repo-check`, `--ephemeral`, `--json`, `--output-last-message`, `--strict-config`, `--ignore-user-config`, `--disable <FEATURE>`, `-s/--sandbox`, `-p/--profile`; флага профиля разрешений (`-P`) у `exec` нет.

По документации профиль разрешений выбирается ключом `default_permissions`, если ни один загруженный конфиг не
задаёт `sandbox_mode` и не передан `--sandbox` (`PERMISSIONS-DOC-20261114.md`). Для `codex exec` на этом ПК это не
проверено.

## Задача пилота (из плана работ)

Неисправленный дефект №2 из `docs/audits/CR-hermes-symphony-serving-lifecycle-20261106-attempt-workspace-20261113/RESULT-20261114.md`:
`require_applies` в `plugins/symphony_pm/transport/attempt_workspace.py` выполняет `git read-tree` и
`git apply --cached --check` в основной копии; страж тестов это запрещает, и проверка patch не работает на стенде.

Задание для Codex: проверять patch в теневом Git-каталоге попытки против базового дерева (оно уже вычисляется в
`Capture.baseline` и совпадает с деревом SHA, когда `baseline_matches_source`), без вызова Git в основной копии;
отказывать, если базовое дерево не совпадает с деревом SHA; добавить fixture-тест на это поведение в
`tests/plugins/test_symphony_pm_attempt_workspace.py`. Объём — два файла. Задача проверяется fixture-тестами без
native-запуска.

## Предлагаемое решение (предложение исполнителя, INFERRED; не решение владельца до `ok`)

1. **Авторизация.** Новый каталог `D:\SymphonyRuntime\codex-home` с `config.toml`: `cli_auth_credentials_store = "file"`.
   Вход через ChatGPT выполняет владелец один раз (`codex login` с этим `CODEX_HOME`, браузер); исполнитель файл
   авторизации не читает и не копирует. Существующие установки Codex не меняются.
2. **Конфигурация пилота** в том же `config.toml`: профиль `":root" = "deny"`, `":minimal" = "read"`, запись только в
   каталог попытки, сеть команд выключена; `windows.sandbox = "mxc"`; `shell_environment_policy` —
   `inherit = "core"`, `ignore_default_excludes = false`; MCP-серверы не заданы; web search и включённые по
   умолчанию приложения и коннекторы отключаются (точные ключи берутся из `codex features list` при реализации и
   записываются в результат).
3. **Рабочая область.** Копия дерева `0ca1eb18` без `.git` через существующий `attempt_workspace.export` во временный
   каталог задания на D: (не в рабочей копии); базовое дерево — `Capture.baseline`.
4. **Предпроверка без модели** с тем же `CODEX_HOME` и профилем (`codex sandbox`): команда не видит значения из
   `auth.json` в окружении и не читает `auth.json`, список `CODEX_HOME`, `config.toml`. Провал — стоп до `codex exec`.
   Конфигурация не содержит `sandbox_mode`, `--sandbox` не передаётся; `-c default_permissions=...` передаётся явно.
4a. **Проверка изнутри `codex exec`.** Первая инструкция промпта — выполнить готовый зонд (без задачи): окружение
   (имена и дайджесты), чтение `auth.json` и приманки вне попытки, запись вне попытки, TCP к loopback. Стенд
   читает отчёт зонда и журнал `--json`; если хоть одно действие удалось или зонд не выполнен первым — стенд
   закрывает Job, задача считается не выполненной, повтора нет.
5. **Запуск.** Один `codex exec --skip-git-repo-check --ephemeral --json -o <файл> -C <src>` с промптом задачи;
   `approval_policy = "never"`; клиент в нашем Job с kill-on-close; окружение клиента без ключей (как в тесте
   авторизации); лимит времени 40 минут, затем закрытие Job. Модель и effort — по умолчанию клиента, записываются.
6. **Результат.** Patch снимает существующий `Capture` (политика путей, отказ на ссылки и `.git*`). Проверка у owner:
   patch применяется к отдельной копии `0ca1eb18` во временном каталоге (не к рабочей копии), там выполняются
   `ruff` по изменённым файлам и `scripts/run_tests.sh tests/plugins/test_symphony_pm_attempt_workspace.py`.
   Patch не применяется к рабочей копии и не коммитится без отдельного решения владельца.

Существующий код `CodexLauncher`, transport и `LifecycleOwner` в пилоте не используются: это один прямой запуск из
стенда. Новых сервисов, учётных записей и системных настроек нет.
