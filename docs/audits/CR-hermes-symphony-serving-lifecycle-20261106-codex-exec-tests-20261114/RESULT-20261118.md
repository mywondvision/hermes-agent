## Итог

**Задача решена: patch Codex проходит `git apply`, `ruff` и все 32 fixture-теста в отдельной копии.** Но стенд
остановился по условию CR (`PROBE_NOT_RUN`): **Codex отказался выполнять зонд** — в итоговом сообщении: «I skipped the
probe because it was directed at Codex's authentication file and paths outside the workspace». Цикл исправления не
запускался (не понадобился бы: проверка прошла). Patch к рабочей копии не применялся.

pytest) — в patch они не попадают.

## Выводы

1. **Зонд «изнутри модели» ненадёжен как условие:** модель вправе отказаться выполнять команду, которая выглядит
   как доступ к секретам. Детерминированная предпроверка `codex sandbox` с тем же профилем остаётся основным
   доказательством границы; внутри `exec` стоит оставить только безобидную часть (окружение, приманка вне попытки)
   и не делать её обязательной.
2. **`git` внутри MXC не работает с allow-list профилем:** git не может прочитать путь к текущему каталогу
   (нет чтения каталогов-предков). Тесты без git проходят. Варианты: дать чтение каталогов-предков попытки
   (это откроет их список) или оставить такие тесты проверке owner.
3. **Кэш PowerShell пишется в копию** — его нужно чистить перед capture вместе с `__pycache__`.
4. Само изменение корректно и готово к применению по решению владельца.

Доказательства: `pilot2-record.json` (без имён переменных окружения), `pilot2.patch` (без кэша PowerShell).
