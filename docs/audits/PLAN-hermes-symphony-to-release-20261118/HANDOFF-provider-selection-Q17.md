# Подбор машины для пилота Hermes Symphony · Q17

**Решение, которое требуется от исследования.** Предложить владельцу конкретную комбинацию «провайдер + тариф + регион + редакция Windows + полная стоимость» для короткой аренды. Указать резервный вариант и способ с минимальными затратами проверить решающее техническое условие. Это исследование рынка. Заказ, оплата и вход в подписку остаются за владельцем.

## Что будет работать на машине

Hermes принимает задание, Symphony управляет попыткой, а Codex CLI запускает команды в песочнице MXC. Модель вызывается по подписке Codex. Для локального запуска модели GPU не требуется. На диске должны сохраняться репозиторий, Python-окружение, журнал SQLite и рабочие каталоги попыток. Пилот включает пять задач длительностью до 120 минут каждая, максимум три попытки в день. Даже при успехе с первой попытки понадобятся как минимум два дня плюс время на настройку и проверку восстановления.

## Почему Windows

Текущий транспорт написан под Windows. Он помещает клиент Codex в Windows Job Object, наблюдает за входящими в него процессами и использует закрытие последнего дескриптора Job для остановки дерева. При восстановлении учитываются личность процесса-владельца и идентификатор загрузки Windows. Эти свойства нужны для ответа на вопрос «предыдущая попытка действительно остановлена и можно ли начать следующую?».

На исходной машине Windows 11 выполнен запуск Codex CLI с MXC; в отдельной проверке после закрытия Job завершился клиент и исчез наблюдаемый долгоживущий потомок. Полноту остановки процессов команд MXC после разных видов отказа проверяет отдельный набор CR-4. На арендованной машине проверки повторяются. Перенос транспорта на Linux — самостоятельная разработка за пределами текущего плана.

## Что считать подходящим предложением

- **Основной кандидат** — Windows 11 x64 с понятными условиями лицензирования, доступом владельца к установке инструментов и возможностью управляемой перезагрузки с сохранением диска. Эталонная версия Codex CLI проекта — 0.167.0.
- **Условный кандидат** — Windows Server x64 или иной образ Windows, на котором провайдер позволяет провести короткую проверку. Совместимость Windows Server с этим профилем MXC проект пока не проверял. Надпись «Windows VPS», доступ по RDP и наличие Hyper-V сами по себе не подтверждают совместимость. Вложенную виртуализацию указывать как требование лишь при наличии основания для конкретного образа и механизма песочницы.
- **Ресурсы** — ориентир проекта от 16 ГБ RAM и от 4 ГБ свободной RAM перед попыткой. Оба значения пока предложены для проверки. Лимит Job клиента в коде — 6 ГБ и 64 процесса. Количество vCPU и объём SSD подобрать с обоснованием; фиксированных минимумов по ним проект не задавал.
- **Решающий тест после выбора и отдельного разрешения владельца** — на реальном экземпляре проходит model-free зонд профиля через `codex sandbox`. Для квалификации CR-H также нужны зелёные fixture-тесты, `doctor` без ошибок и проверки остановки CR-4 без модели. Документация тарифа позволяет составить шорт-лист; фактическую квалификацию можно подтвердить только на машине.
- Владелец сам выполняет вход в Codex. Секреты, адрес будущей машины, платёжные данные и материалы рабочих репозиториев исследователю не требуются. Бюджет, платёжная юрисдикция и обязательный регион пока не заданы.

## Готовый промпт для исследователя

> Подбери арендованную Windows-машину для пилота Hermes Symphony по приложенному handoff. Работай только с публичными источниками. Нужен выбор конкретного тарифа с возможностью дешёвой проверки совместимости до длительной аренды. Заказы, регистрацию, переписку с поддержкой и запуск ВМ оставь владельцу.
>
> 1. Найди до трёх доступных к заказу вариантов на дату исследования. Приоритет — легально предоставляемая Windows 11 x64. Если есть только Windows Server или установка собственного образа, укажи точную редакцию, условия лицензии, необходимые права и что остаётся выяснить. Когда доступность видна только после входа, пометь её как неподтверждённую.
> 2. Для каждого варианта дай прямые ссылки на официальный тариф, список образов и правила биллинга. Укажи регион, vCPU, RAM, тип и объём постоянного диска, способ удалённого доступа, права на установку ПО и возможность перезагрузки. Отдельно проверь ограничения на запуск фонового gateway и доступ клиента к сервису Codex. У каждой важной характеристики различай сведения провайдера и вопросы для проверки на машине.
> 3. Посчитай стоимость в исходной валюте для короткой пробной аренды (2 часа, если доступно), 48 часов непрерывной работы и месяца. Покажи лицензию Windows, диск, IP при необходимости, налог если известен, минимальный платёж и расходы после выключения. Если тариф помесячный, покажи реально списываемую минимальную сумму. При неизвестном налоге укажи сумму до налога. Если регион или способ оплаты меняют выбор, укажи при каком условии меняется рекомендация.
> 4. Результат — компактная таблица и два конкретных выбора: какой тариф проверить первым и каким заменить при неудаче. Для каждого назови главный риск. Если остаются вопросы о лицензии, правах или возврате, составь короткое сообщение для поддержки, которое владелец сможет отправить сам.
> 5. Заверши последовательностью первой проверки после отдельного согласия владельца: условия списания → образ и права → перезагрузка и сохранность диска → model-free проверка MXC средствами проекта → решение продолжать или освободить машину. Укажи максимальную необратимую стоимость этой проверки. Если достоверного предложения для Windows 11 найти не удалось, объясни причину и предложи условный вариант с проверяемым риском.

**Критерий ответа по Q17.** Владелец может назвать одного провайдера, тариф, регион и ОС, понимает минимальную сумму риска и знает, какая проверка позволит принять или отклонить машину. После выбора оркестратор готовит CR-H.
