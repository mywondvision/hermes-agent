## 2. Что найдено сверх ред. 1 (новые факты F15–F27)

Самое важное — три факта, которые меняют приоритеты:

1. **F15.** После перезагрузки хоста владелец не создаётся никогда: `HOST_BOOT_CHANGED_HOLD` (`lifecycle.py:115-118`),
   пути очистки нет. CONFIRMED.
2. **F16.** После любого рестарта gateway при связанной записи запуска владелец не создаётся: наблюдатель ищет Job
   в реестре, локальном для процесса (`windows_api.py:15-18`, `107-112`), и отказывает; поведение закреплено
   native-тестами как намеренное удержание. Вместе с F5 это означает: текущий код — «один запуск на namespace на
   один boot в одном процессе». Ред. 1 видела только «следующий запуск отклоняется». CONFIRMED.
3. **F7/F17.** Job попытки не закрывается после завершения клиента, capture идёт без доказанного стопа; при
   TIMEOUT с неотправленной отменой клиент Codex продолжает работать без лимита до выхода gateway. CONFIRMED (код).

Остальное: F18 (основание для доказательства стопа по учёту Job), F19 (предпроверка входит в ОС; признак «не
начато» — незанятый слот create), F20 (окно свежести receipt делает невозможным наблюдение «со своим временем»),
F21 (статус недоступен до binding и после истечения permit), F22 (permit проверяется ещё дважды до resume),
F23 (одна попытка на хост; репозиторий не входит в план), F24 (slash-команды, injection и Telegram-обработчики
плагина уже есть в ядре), F25 (правило `spawn_context_thread`; окружение owner-side git), F26 (терминал по
умолчанию локальный), F27 (рестарт gateway убивает попытку).

## 6. Вопросы к владельцу (актуальный список)

Полные формулировки — раздел 5 архитектуры. Новые или изменённые относительно ред. 1 помечены.
