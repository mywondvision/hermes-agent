# Результат: граница worker → owner (design/prototype slice, 2026-11-12)

CR: `docs/change-requests/CR-hermes-symphony-serving-lifecycle-20261106-worker-boundary-20261112.md`.
База: `623ca1e3`.

## Статус

**Прототип готов и проверен offline. Native-проверки не запускались (`NOT_RUN`): нужен допуск владельца.**
Находка N2 (воркер дублирует хендл Job из owner) остаётся **не закрытой**, пока native-проход A3–A6 не выполнен.
Fixture-тесты доказывают логику отказа, но ни один вызов Windows для токена offline не исполняется.

## Что изменено

| Было | Стало |
|---|---|
| Воркер рождался с токеном owner | Воркер рождается с ограниченным токеном: привилегии сняты, целостность Low |
| Проверки границы не было | До resume owner проверяет: воркер — Low, сам owner — ровно Medium; иначе `WORKER_BOUNDARY_UNENFORCED` |
| — | Пути создания воркера с токеном owner нет; сбой токена — отказ, слот create остаётся потраченным |
| Synthetic-воркер писал в каталог профиля | Воркер пишет только в каталог стенда с меткой Low |
| Диагностический зонд N2 (без утверждений) | Контрактный тест: отказ на открытие owner, запрет записи вне копии |

Схема и формат журнала, fencing, запрет повторного create, `UNSETTLED_PRIOR_LAUNCH_HOLD` не изменены.

## Сравнение вариантов (кратко; полностью — в CR)

- Ограниченный токен Low: закрывает дублирование и запись в файлы owner без прав администратора и без системных
  настроек; атомарное рождение в Job сохраняется. Чтение секретов не ограничивает.
- Отдельный пользователь: ограничивает и чтение, но требует создания учётной записи и ломает атомарное рождение.
- DACL процесса owner: не мешает воркеру писать журнал и код owner — как основная мера отклонён.

## Учтённые замечания code review

1. Owner с повышенными правами теперь отклоняется: `DISABLE_MAX_PRIVILEGE` не снимает группу администраторов.
2. Контрактный тест проверяет, что отказ получен именно на процесс owner (`owner_pid`), и фиксирует (не
   утверждая) открытие с `PROCESS_TERMINATE` и `PROCESS_QUERY_LIMITED_INFORMATION`.
3. Параметр токена в `create_suspended` обязателен; `None` передают только тестовые процессы-owner.
4. В «Существенные неизвестные» CR добавлены: соседи с целостностью Low, завершение owner воркером, loopback.

Не исправлено: при сбое `CloseHandle` исходного токена возможна утечка одного хендла (сбой закрытия собственного
хендла не воспроизводится); fixture-тест импортирует autouse-фикстуру из соседнего тестового модуля.

## Observer, наследование, другие процессы

- Observer живёт в процессе owner. Его дубликат Job (право только QUERY) не наследуется и закрывается после
  каждого чтения; при аварии owner оба хендла закрывает ядро. Наружу observer отдаёт значение `StopReadback`.
  Native-тест A4 роняет owner внутри чтения observer.
- Хендл Job, оставшийся в **другом** процессе, удерживал бы Job даже с правом только на чтение. Поэтому правило
  контракта: хендлы не покидают owner; внепроцессный наблюдатель получает снимки.
- Воркеру наследуются только три стандартных потока.
- Остаётся открытым: процессы того же пользователя со средней целостностью (включая команды terminal-tool самого
  Hermes) могут продублировать хендл из owner; соседи с целостностью Low могут вмешаться в воркер.

## Что реально нужно настоящему driver (не измерено)

| Потребность | Под целостностью Low | Статус |
|---|---|---|
| Читать исполняемый файл, окружение, рабочую копию | разрешено | ожидается, не измерено |
| Писать в рабочую копию | только если каталог помечен Low | прототип — в стенде; production-привязки нет |
| Писать каталог сессий и обновлять авторизацию driver | запрещено без отдельного каталога Low | UNKNOWN |
| Читать учётные данные driver | разрешено — вместе со всеми секретами пользователя | риск, срез не ограничивает |
| Сеть до провайдера модели | не ограничена | UNKNOWN |

## Что существует в ките и что не подтверждено

Существует и исполняется кодом: Context Hygiene Gate (prefilter, pack, независимость ревьюера, validate, status,
handoff), базовые правила allow/ask/deny и проверка doctor. Существует как текст регламента: классы риска
R0–R3, триггеры CR, роли и делегирование (один писатель, глубина один), tester и уровни доказательств, один
корректирующий проход. Не найдено в основном ките: активная маршрутизация моделей по ролям (схема и резолвер есть
только во втором checkout и выключены по умолчанию), блокирующий PreToolUse-hook, долговременный допуск на класс
тестов, маршрут к голосовому интегратору, упоминания Hermes/Symphony.

Этот срез выполнен существующими механизмами: CR → hygiene gate → делегирование реализации тестов → независимое
code review → корректирующий проход. Параллельный оркестратор не создавался.

## Ограничение автономного цикла, найденное в transport

Namespace допускает один запуск: после любого запуска действует `UNSETTLED_PRIOR_LAUNCH_HOLD`, а settlement и
release остаются HOLD. Цикл «ревью → исправление вторым запуском» через Hermes → Symphony сейчас невозможен.
Внутри одного запуска воркер может сам повторять «инструмент → исправление → инструмент» (тест A6).
