## Статус

**Срез реализован. Корректирующий native-проход без модели: `7 files, 17 tests passed, 0 failed`.**
Первый проход не прошёл (`7 files, 8 tests passed, 9 failed`) из-за ошибки тестового стенда; состав списка
restricting SID между проходами не менялся. Корректирующий проход владелец разрешил отдельно («ok, запускай ещё

## Что открывает воркеру состав списка

Список: SID попытки, Everyone, Users, Authenticated Users, RESTRICTED. Воркер получает доступ только к тому, что
пускает и пользователя (обычная проверка), и хотя бы один SID из списка (вторая проверка).

- **Authenticated Users и Users** — чтение всего, что эти группы могут читать: системные файлы, интерпретатор и,
  на этом хосте, весь диск с рабочими деревьями (корень диска даёт Authenticated Users право изменения). Запись
  туда блокирует низкая целостность, чтение — нет. Это подтверждено диагностикой выше.
- **RESTRICTED** — оконная станция и рабочий стол сеанса, каталог именованных объектов сеанса (только проход),
  системные устройства случайных чисел. Что ещё пускает этот SID (например, ветки реестра пользователя), не
  проверялось.
- **Не входит:** SID пользователя и SID сеанса входа. Поэтому закрыты объекты, которые пускают только их:
  процессы пользователя с любой целостностью, файлы профиля.

## Что не доказано и остаётся открытым

- Проверены только объекты, чьи права созданы по умолчанию этим пользователем. Процессы других пользователей,
  AppContainer и объекты с правами для Everyone или Authenticated Users не проверялись.
- Чтение файлов вне профиля, доступных группе Authenticated Users, открыто (подтверждено).
- Не проверялись: выход через WMI, COM и планировщик задач; сеть и loopback; реестр; UI без ограничений Job.
- Процессы того же пользователя со средней целостностью по-прежнему могут продублировать хендл Job из owner.
- Настоящий driver под таким токеном не запускался. В production у воркера нет каталога, куда он может писать, и
  нет каталога, который выдаёт доступ SID попытки: без следующего среза (путь записи) driver не заработает.
- `windows_topology_diagnostic` в проходы не входит и под воркер с низкой целостностью не обновлялся.

## Не исправленные замечания ревью

- Проверка границы не отличает токен с флагом «ограничение только на запись»; этот код такой токен не создаёт.
- `with_grant` для объекта без DACL создал бы DACL из одной записи; DACL по умолчанию у токена есть всегда.
- Ошибка закрытия хендлов при отказе границы скрывает исходную причину за `OWNED_HANDLE_CLOSE_UNKNOWN`.
- Выдача доступа стендом на домашний каталог теста заново распространяет наследуемые права по его поддереву.
