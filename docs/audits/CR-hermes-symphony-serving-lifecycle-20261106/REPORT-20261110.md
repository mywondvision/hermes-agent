# Hermes → Symphony: отчёт по Windows serving lifecycle

Дата: 2026-11-10.

## Результат

Разрешённый synthetic native этап завершён: **5 PASS, 0 FAIL**, один проход без повторов, **12,875 с**. Проверены takeover, потерянный ACK и три границы смерти serving process. Сохранённые наблюдения подтверждают **14 уникальных идентичностей процессов**; для всех получен terminal readback, ошибок cleanup нет. В effect-before-ACK оба измеренных worker-member остановлены до последующей parent cleanup.

**Native/global cancel, release и production readiness остаются HOLD.** Это приёмка выбранных synthetic Windows lifecycle scenarios, а не реального Codex/model stop.

В Git публикуется только этот сводный отчёт. Новая runtime/test CODE остаётся локальной; commit/push исходников, installation и deployment этим этапом не выполнялись. Подробные диагностические данные и внутренние идентификаторы в отчёт не включены.

## Проделанная работа

- Подготовлены конкретные Windows ownership guard, query observer, native receiver и явная привязка к существующему host lifecycle.
- Реализованы устойчивые process/Job identities, suspended create, durable binding до resume, query-only observation и kill-on-close.
- Launcher использует существующий kit CodexDriver; его schema, model, effort, budget, bypass и result checks не дублируются. Второй orchestrator, queue, HTTP-сервис или daemon не создавался.
- Durable CREATE_INTENT записывается до OS entry и запрещает повторный create после uncertain outcome.
- Resume и cancel проверяют writer fencing на native boundary; epoch, observer generation и spent effect не восстанавливают право на повторный send.
- Predecessor identity mismatch теперь означает HOLD согласно CR.
- Подготовлена и проверена synthetic crash matrix: старый callback отвергается после rotation, потерянный ACK не выдаёт повторный sender, recovery не запускает replacement worker.
- Независимые reviewers проводили read-only проверки. Worktree имел одного writer; чужие изменения сохранены.

Самая первая fixture попытка завершилась до тестов из-за отказа доступа при старте Git Bash; отдельный повышенный повтор был разрешён владельцем. Каждый operational проход имел собственный допуск, retries=0. Неуспешные результаты сохранены в истории работы и не заменяются поздними PASS.

Числа не суммируются: наборы и source revisions различаются и пересекаются. Прежние 114 PASS и 24 PASS также были пересекающимися fixture campaigns и не доказывали native runtime.

Причина topology failures установлена диагностикой: ожидание одного Python root было неверным, поскольку Job содержит также console host. Harness исправлен без исключения дополнительных members по имени: наблюдаются все exact identities, действуют kernel limits и отдельные cumulative counters. В пяти финальных scenarios подтверждён бюджет 14 процессов. Независимый reviewer проверил log и все сохранённые proofs.

## Незакрытые критерии

- **Production create→Job assignment gap сохраняется.** Смерть owner до assignment может оставить suspended orphan. Проверены HOLD/no-relaunch и отдельная страховочная cleanup стенда; production gap этим не устранён.
- Реальный CodexDriver/model stop, production approval source и qualified driver/environment bindings не приняты и не установлены.
- Reboot, power-loss, remote inference, billing settlement и внешние последствия остаются UNKNOWN.
- Raw SQLite rows после тестового scratch cleanup не сохранены: SQL invariants подтверждены прошедшими assertions; отдельные identities/counters/terminal proofs сохранены.
- Полный lint/CI не выполнялся. Голосовой hotkey, живая русская речь, ASR FINAL/cancel и готовность Bimo учитываются отдельно.
- Микрофон, передача живого голоса, платные ресурсы, установка в S3 и production не запускались.

Цель голосовой цепочки сохраняется: «горячая клавиша → речь → Hermes → ответ → разрешённое действие или сессия». Результаты lifecycle не повышают готовность голоса. При потере удалённого ASR должны оставаться local STOP и текстовый ввод.
