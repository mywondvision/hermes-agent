# Проверка чтения для токена воркера (2026-11-13, до CR, без native-запуска)

Метод: в процессе исполнителя создаётся токен воркера тем же кодом `windows_token.py` (вершина `0a46b771`),
дублируется как токен имперсонации, и для каждой цели вызывается `AccessCheck` с её фактическим дескриптором
(владелец, группа, DACL, метка). Процесс воркера не запускается, содержимое файлов и ключей не читается.
Скрипты: `probes/read_probe.py`, `probes/read_variants.py`, `probes/deny_probe.py` (запуск:
`python -X utf8 <script> <worktree>`; `deny_probe.py` меняет DACL только своего временного каталога).

Ограничение метода: `AccessCheck` проверяет сам объект. Проверку прохода по родительским каталогам он не
моделирует; её подтверждает только настоящий процесс.

## 1. Текущий токен (Low + restricting SID: попытка, Everyone, Users, Authenticated Users, RESTRICTED)

`read-preflight-current-token.json`:

| Цель | Чтение | Запись |
|---|---|---|
| Файл учётных данных Claude Code на диске D | **разрешено** | отказ |
| `.env` в другой копии на D | **разрешено** | отказ |
| Каталог приватных пакетов на D | **разрешено** | отказ |
| `.ssh` и `.codex` в профиле пользователя | отказ | отказ |
| `.git/config` и файлы этого рабочего дерева, файлы другой копии | разрешено | отказ |
| Интерпретатор, системная DLL | разрешено | отказ |
| `HKCU\Environment` (переменные пользователя, в т.ч. ключи API — только имена проверены) | **разрешено** | отказ |
| `HKCU\Software` | разрешено | отказ |

Запись везде запрещает низкая целостность (no-write-up), чтение — нет.

## 2. Откуда чтение (фактические ACL)

- Корень `D:\` даёт Authenticated Users изменение, Users — чтение и выполнение, с наследованием; каталоги
  `D:\Claude`, `D:\AI`, `D:\AI\worktrees`, `D:\AI\preserve` наследуют это. Профиль на C: пускает только
  пользователя, администраторов и SYSTEM.
- `HKCU` и `HKCU\Environment` дают чтение `RESTRICTED` (S-1-5-12), ALL APPLICATION PACKAGES и одной capability.

## 3. Варианты списка restricting SID (`read-preflight-variants.json`)

| Список | Секреты на D | `HKCU\Environment` | Интерпретатор и системная DLL |
|---|---|---|---|
| текущий | читаются | читается | читаются |
| без Authenticated Users | **читаются** (через Users) | читается | читаются |
| без Authenticated Users и Users | закрыты | **читается** (через RESTRICTED) | **закрыты** — процесс не стартует без нового механизма |
| только попытка + RESTRICTED | закрыты | читается | закрыты |

Вывод: удаление Authenticated Users ничего не меняет; удаление Users закрывает и системные файлы; RESTRICTED
(без него процесс не получает оконную станцию и рабочий стол) оставляет чтение `HKCU`. Сужением списка задачу
«не читать секреты» на этом хосте не решить.

## 4. Запрет через SID класса воркеров (`deny_probe.py`, свой временный каталог)

Запись DENY (чтение и проход) для SID, который есть только в списке restricting SID воркера:

| Токен | До записи | После |
|---|---|---|
| воркер без SID класса | разрешено | разрешено |
| воркер с SID класса | разрешено | **отказ** |

Токены без этого SID (пользователь, его обычные процессы) запись не затрагивает. `icacls` SID вида `S-1-9-…`
не принимает (ошибка 1332), запись ставится через `SetEntriesInAclW` + `SetFileSecurityW` без распространения
на дочерние объекты.

## 5. Ресурсы хоста на момент проверки

Свободно RAM 1,7 из 13,9 ГБ, файл подкачки 10,5 ГБ, C: 4,2 ГБ, D: 694 ГБ. Дерево на `0a46b771`: 22 233 файла,
около 230 МБ. `python scripts/check` при таком запасе памяти не запускался.
